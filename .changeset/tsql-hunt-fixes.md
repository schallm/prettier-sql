Fixes found by formatting Microsoft's ScriptDom test scripts:

- `OPTION (BYPASS OPTIMIZER_QUEUE)` and `OPTION (OPTIMIZE CORRELATED UNION ALL)` no longer fail to format.
- `OUTPUT … INTO @t` followed by a plain `OUTPUT …` keeps both clauses on `INSERT`, `UPDATE`, `DELETE` and `MERGE`; the plain `OUTPUT` was dropped.
- A `NULL` principal in `GRANT`, `DENY` and `REVOKE` (`TO public, null, u`) is kept; it printed as nothing, leaving `public, , u`.
- Qualified names keep every part: `ENABLE / DISABLE TRIGGER db.schema.trg`, a type's schema in `dbo.MyType::Method()`, and a `PIVOT`'s aggregate (`dbo.MyAggregate`) and column qualifiers (`t.Amount`); all but the last part were dropped.
- `WITH CHANGE_TRACKING_CONTEXT (…)` followed by CTEs prints as one `WITH` (it printed as two, which doesn't parse), and `MERGE` keeps its change-tracking context. `INSERT`, `UPDATE`, `DELETE` and `MERGE` keep a `WITH XMLNAMESPACES (…)`; both were dropped.
- `CREATE MATERIALIZED VIEW … WITH (DISTRIBUTION = HASH(…) | ROUND_ROBIN, FOR_APPEND)` and `ALTER MATERIALIZED VIEW … REBUILD | DISABLE` are formatted; they printed as a plain `CREATE VIEW` with broken options, or an empty `ALTER VIEW … AS`.
- Multi-word type spellings keep their type: `char varying(10)` became `char(10)`, `national char varying` and `nchar varying` lost `varying` or `national`. They now print as `varchar`, `nvarchar`, `nchar`, `varbinary` and `ntext`.
- Qualified pseudo-columns keep the pseudo-column: `t.identitycol`, `a.b.rowguidcol`, `t.$identity` and `t.$rowguid` printed as just `t` (or `a.b`). A full-text predicate's `t.*` keeps its table; it printed as `*`.
- `UNPIVOT (… IN (t.c0, c1))` keeps each column's qualifier.
- `IDENTITY(+100000, -2)` keeps a signed seed and increment; they were dropped, leaving `IDENTITY` (1, 1).
- A computed column keeps its constraints (`c AS a + b UNIQUE`, `PERSISTED PRIMARY KEY`, `CHECK`, `REFERENCES`); only `NULL` / `NOT NULL` was kept.
- A column-level `PRIMARY KEY` / `UNIQUE` or `FOREIGN KEY` keeps its column list (`c varchar(9) PRIMARY KEY (id ASC)`, `c int FOREIGN KEY (other) REFERENCES t (x)`); without it the constraint applied to the column it was written on, which can be a different column.
- `ALTER TABLE … DROP CONSTRAINT a WITH (…), b WITH (…)` keeps each constraint's options with it; they were all moved onto the last one.
- `ALTER COLUMN c ADD | DROP ROWGUIDCOL` (and the other `ADD` / `DROP` forms) keeps its `WITH (ONLINE = …)`.
- `ALTER DATABASE … SET AUTO_CREATE_STATISTICS ON (INCREMENTAL = ON)` keeps `INCREMENTAL`.
- `UPDATE STATISTICS … WITH RESAMPLE ON PARTITIONS (…)` keeps its partitions; it resampled every partition.
- `DECLARE @v int NOT NULL = 4` (and `NULL`) keeps its nullability.
- `SELECT … INTO t` in the first query of a `UNION`, or inside parentheses, keeps its `INTO`; it was dropped, so the query returned rows instead of creating the table.
- A cursor's query (`DECLARE c CURSOR FOR …`, `SET @c = CURSOR FOR …`) keeps a leading `WITH cte AS (…)` and a trailing `OPTION (…)`; both were dropped.
- An inline table-valued function's `RETURN (WITH … SELECT …)` keeps its CTEs and `XMLNAMESPACES`.
- A CLR table-valued function keeps its `ORDER (…)` hint.
- `JSON_OBJECTAGG(…) OVER (…)` and `JSON_ARRAYAGG(… ORDER BY …) OVER (…)` keep their `OVER`; without it they aggregated the whole result.
- `OPENROWSET(BULK …)` keeps every data file in `BULK ('f1', 'f2')`, an `AS a (c1, c2)` column list, `ORDER (…) UNIQUE`, and the values of `HEADER_ROW = TRUE` and `ROWSET_OPTIONS = '…'` (which printed without a value and didn't parse).
- `GRANT` / `DENY` / `REVOKE … ON SERVER::name` keeps the server's name.
- A column written as just `timestamp` (`CREATE TABLE t (timestamp NOT NULL)`) no longer gains a type: it printed as `timestamp int`.
- Bracketed names inside option text keep their case (`CREDENTIAL = [Bob's Key]`); keyword casing changed them, and an apostrophe inside one could recase a string literal after it.
- Names in option values keep their case under keyword casing: `CREDENTIAL = UserCredential`, `DEFAULT_LANGUAGE = English`, `NAME = LibraryData`, and the columns of a columnstore index's `ORDER (ColA, ColB)`.
- `ALTER DATABASE … SET DB_CHAINING`, `VARDECIMAL_STORAGE_FORMAT`, `ARITHABORT` and `NUMERIC_ROUNDABORT` keep their names; they printed as `dbchaining`, `var_decimal_storage_format`, `arith_abort` and `numeric_round_abort`, which don't parse.
- `ALTER DATABASE … SET PARTNER SAFETY FULL | OFF` and `PARTNER TIMEOUT 10` keep `SAFETY` and `TIMEOUT`; they printed as `PARTNER FULL` and `PARTNER 10`, which don't parse.
- `a IS [NOT] DISTINCT FROM ALL | ANY | SOME (subquery)` prints its operator; it printed as `IsDistinctFrom`, which doesn't parse.
- `CREATE INDEX … WITH PAD_INDEX, FILLFACTOR = 80` (SQL Server 2000 options, without parentheses) prints as `WITH (PAD_INDEX = ON, FILLFACTOR = 80)`; it printed `WITH (PAD_INDEX, …)`, which doesn't parse.
- A column's clauses print in the order T-SQL accepts: `HIDDEN` after `MASKED WITH (…)` and before `IDENTITY` / `ROWGUIDCOL`, `SPARSE` / `FILESTREAM` before `IDENTITY` and `ROWGUIDCOL`, and `GENERATED ALWAYS` before `SPARSE`; the output didn't parse.
- `BACKUP` / `RESTORE … FILE = ('f1', @f2)` and `FILEGROUP = (@a, @b)` keep their parentheses; without them the output didn't parse.
- A user table-valued function named `AI_GENERATE_CHUNKS` keeps its brackets (`dbo.[AI_GENERATE_CHUNKS](SOURCE)`); without them it read as the built-in function and didn't parse.
- `SERVICE_OBJECTIVE = ELASTIC_POOL (NAME = pool)` in `CREATE DATABASE` and `ALTER DATABASE … MODIFY` keeps its closing parenthesis; the output didn't parse.
- `EXEC (…) AS LOGIN` with no name no longer prints a dangling `= `, which didn't parse.
- `ALTER PARTITION FUNCTION f() SPLIT` / `MERGE` with no range prints as written; it printed `SPLIT RANGE ()`, which doesn't parse.
- `{fn EXTRACT(HOUR FROM x)}` no longer prints as `{fn extract(extract(hour from x))}`, which didn't parse.
- Graph pseudo-columns (`$node_id`, `$edge_id`, `$from_id`, `$to_id`) are kept in index keys and `INCLUDE (…)`; they printed as nothing (`ON t ()`), or failed to format. `CREATE TABLE t AS EDGE` with no columns no longer prints an empty `()`.
- `ADD CONSTRAINT c FOREIGN KEY REFERENCES t (x)` (no column list) no longer prints `FOREIGN KEY ()`, which didn't parse.
- A function call written `.f()` (the default schema's function) keeps its leading dot; without it the call was to a built-in function.
- `DBCC … WITH STAT_HEADER JOIN DENSITY_VECTOR` follows `sqlKeywordCase` for `JOIN`; it was always upper case, so with `preserve` a second format changed the output.
- `ALTER DATABASE … SET QUERY_STORE CLEAR ALL` keeps `ALL`; it printed as `QUERY_STORE CLEAR`.
- `ALTER DATABASE SCOPED CONFIGURATION SET option = -10` keeps its number; it printed as `= -`, which didn't parse.
- `OPTION (USEPLAN 2)` keeps its one-word spelling; it printed as `USE PLAN 2`, which doesn't parse.
- `CREATE TABLE`, `ALTER TABLE … ADD`, `DECLARE @t TABLE (…)`, `CREATE TYPE … AS TABLE (…)` and a function's `RETURNS @t TABLE (…)` keep columns, constraints and indexes in the order written; columns were moved first, which reordered their comments too.
- With `sqlKeywordCase: 'preserve'`, a short statement with none of the common keywords (`END;`, `CLUSTER t`, `COPY … TO STDOUT`) keeps the case its first word is written in; it fell back to lower case, and formatting upper-case output again could change its case.
- A comment after a column or constraint of a function's `RETURNS @t TABLE (…)` stays with it; it was moved up after the function's name.
